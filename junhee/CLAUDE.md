### 같은 성격의 추가 금지 (현재 보유 자료에 바로 걸리는 것)

- **미국 관세표를 다른 국가의 관세 자료로 사용하지 않는다.** (명세서 §7)
- **과거 평가 실행을 최신 자료로 조용히 다시 계산하지 않는다.** 입력·규칙·외부 자료가 바뀌면 새 평가 실행으로 저장한다. 화면과 보고서는 같은 평가 실행을 참조한다. (명세서 §6)
- **OECD 국가위험분류의 `-`·미분류를 0 이나 최저위험으로 환산하지 않는다.** ‘분류 대상 아님’은 ‘위험 없음’이 아니다. (`api-vault/reference_data/README.txt`, registry 비고)
- **관세청 국가별 관세율표는 법적 효력 없는 참고용**임을 유지한다. 확정 관세율 근거로 단독 사용하지 않는다. (registry 비고)
- **CSV 원본을 Excel 로 열어 저장하지 않는다.** 숫자형 코드(`3818.00` → `3818`)와 한글이 손상된다. `raw` 원본은 수정·줄바꿈 변환하지 않는다. (`api-vault/reference_data/README.txt`, CONTRIBUTING §7)
- **실행하지 않은 검증을 통과했다고 쓰지 않는다.** 실제 실행한 것과 미검증 항목을 구분해 기록한다. (명세서 §12, CONTRIBUTING §9·§12)

## 3. `api-vault/` 취급 규칙

- **`api-vault/API_KEYS_FORM.txt` 와 `api-vault/credentials/` 는 열지도 출력하지도 않는다.**
  - `credentials/.env`, `credentials/.env.bak` 포함. 읽기·grep·요약·경로 출력 이상의 내용 노출 금지.
  - 이 두 경로는 Git 에 올리지 않는다(이미 `.gitignore` 에 포함).
- **키는 반드시 `api-vault/scripts/api_keys.py` 의 `get_key()` / `require_key()` 로만 읽는다.**
  - `get_key(name)` → 없으면 `None`, `require_key(name)` → 없으면 예외.
  - `.env` 를 직접 파싱하거나 키를 코드에 하드코딩하지 않는다.
  - 탐색 순서는 ① OS 환경변수 ② `api-vault/credentials/.env` ③ CWD 의 `.env` 이며, **이미 설정된 환경변수를 덮어쓰지 않는다.** 배포 환경의 환경변수 설정이 우선한다.
- **입력표에 키를 추가·변경한 뒤에는 `python scripts/build_env.py` 로 `.env` 를 재생성해야 반영된다.**
  - 입력표만 고치면 `.env` 는 이전 값 그대로 남는다. `api_keys.missing()` 은 이름을 입력표에서·값을 `.env` 에서 읽으므로, 이 상태에서는 “아직 발급 안 됨”과 “발급했는데 `.env` 가 오래됨”이 똑같이 보인다.
  - 재생성 후 `python scripts/check_keys.py` 로 건수를 확인한다. `build_env.py` 는 기존 `.env` 를 `.env.bak` 으로 백업한 뒤 덮어쓰므로, **`.env` 를 직접 손으로 고쳐 두면 재생성 시 사라진다.** 수정은 항상 입력표에서 한다.
- **키 값을 화면·로그·커밋·PR 본문·캡처·채팅에 절대 출력하지 않는다.**
  - 설정 여부 진단이 필요하면 `api-vault/scripts/check_keys.py` 방식(앞 4자리와 길이만)만 사용한다.
  - `api_keys.available()` / `missing()` 은 **이름 목록**만 돌려주므로 진단에 사용해도 된다.
- **현재 사용 가능한 키 목록은 `api-vault/registry/api_registry.csv` 의 `status` 와 `verified` 컬럼으로 판단한다.**
  - `status`: `발급완료` / `미신청` / `재발급필요` / `다운로드완료` / `키불필요`
  - `verified`: `미검증` / `검증완료 <날짜>` / `원문대조 필요` / `-`
  - 레지스트리에는 **키 값을 적지 않는다.** 환경변수 이름만 적는다.
  - `expires_date` 를 확인한다. 만료 전 갱신이 필요하다.
- 공공데이터포털 인증키는 활용자당 1개이며 Encoding·Decoding 두 형태로 발급된다. API 마다 한쪽만 동작하는 경우가 있으므로 400 오류 시 반대쪽을 시도하고, 어느 쪽이 동작했는지 registry 의 `note` 에 기록한다.
- 키가 노출되면 파일에서 지우는 것으로 끝내지 않는다. 즉시 담당자에게 알리고 폐기·재발급하며 Git 이력 정리를 조율한다. (CONTRIBUTING §6)
- `api-vault/` 내부 파일(registry·MANIFEST 포함)은 승인 없이 수정하지 않는다.

## 4. 현재 데이터 가용 상태

`api-vault/registry/api_registry.csv` 와 `api-vault/reference_data/MANIFEST.csv` 기준(2026-09-22 확인). **두 CSV 가 단일 진실 출처이고, 이 절은 요약이다. CSV 가 갱신되면 이 절도 함께 고친다.**

> **가장 중요한 사실: 발급완료된 API 26건 중 25건이 `verified=미검증` 이다. 실제 응답 구조·단위·기간을 확인한 API 는 법제처 국가법령정보 Open API 1건뿐이다. 파일 자료도 원문 대조가 끝나지 않았다.**

### 4.3 사용 불가·미신청

- **`OPENAI_API_KEY`** — 2026-09-22 노출로 기존 키 폐기. 재발급된 키가 입력표와 `.env` 에 반영되어 현재 **설정됨**. 단 **`registry` 의 `status` 는 아직 `재발급필요`, `verified` 는 `-`** 이므로 대장 갱신이 필요하고, 실제 호출 검증 전에는 AI 설명·요약 기능이 동작한다고 전제하지 않는다.

## 5. 미확정 사항 — 사용자 승인 없이 결정하지 않는다

명세서 §2 「개발 전에 결정할 항목」과 CONTRIBUTING §1 에 해당한다. 아래는 아직 정해지지 않았다.

- **기술 스택** — 서버·데이터베이스·파일 저장소·배포 환경, Python/Node 버전, 의존성 관리 방식, 프런트엔드 패키지 관리자, 필수 CI 명령
- **초기 지원 제품군·목적국·규제 검토 범위** (반도체 제품군·대상국 제한으로 시작한다는 방향만 있고 구체 범위 미정)
- **시연용 서비스인지 실제 기업 사용을 받는 서비스인지**
- **로그인 방식**, 조직·사용자 역할, 데이터 보관·삭제 기간
- 파일 크기·행 수·시트 수·처리시간 제한
- 점수 항목·가중치·임계값과 그 검토·승인 절차
- 상세(책갈피) 탭의 최종 구성, 작은 화면 전환 기준
- 요금제·결제 도입 여부

필요하면 **제안은 하되 정해진 것처럼 코드·설정·문서에 굳히지 않는다.** 결정이 필요한 시점에 묻고, 결정되면 명세서 §14 변경 관리 표에 이력을 남긴다.

## 6. 작업 관례 요약 (CONTRIBUTING)

세부는 원문을 따른다. 자주 걸리는 것만 적는다.

- **파일·폴더명**: 폴더·일반 문서 `kebab-case`, Python `snake_case`, React 컴포넌트 `PascalCase.tsx`, 기타 JS/TS `kebab-case`, 환경변수 `UPPER_SNAKE_CASE`. 공식 원본자료는 한글 원본 파일명을 유지해도 된다.
- `final`·`final2`·`진짜최종`·개인 이름으로 버전 관리하지 않는다. 대소문자만 다른 파일을 만들지 않는다.
- 코드·설정·Markdown 은 **UTF-8 / LF**. 원본 HWP·PDF·XLSX 는 변환하지 않는다. Python 은 공백 4칸.
- **개인 PC 절대경로·사용자명·바탕화면 경로를 코드·설정에 하드코딩하지 않는다.** 프로젝트 기준 상대경로 또는 환경설정으로 해석하고 Python 은 `pathlib` 을 쓴다.
- 가상환경은 프로젝트 루트 `.venv` 하나로 통일하고 공유하지 않는다. 의존성 관리 방식을 임의로 혼용하지 않으며, 패키지 변경 시 소스 명세와 잠금 파일을 함께 바꾼다.
- **Git**: `main` 직접 push 금지, 작업 브랜치 `feat|fix|docs|chore/<issue>-<topic>`, Squash merge, 작성자 외 1명 승인. 커밋 전 `git status` 와 staged diff 를 확인하고 `git add .` 로 키·원본·생성파일이 섞이지 않게 한다.
- 한 PR 은 하나의 목적. 무관한 리팩터링·전체 포맷 변경을 섞지 않는다.

> 참고: 이 폴더는 현재 Git 저장소가 아니다. 저장소 초기화·원격 설정은 사용자 결정 사항이므로 임의로 실행하지 않는다.
>
> `git init` 을 할 때 주의: **하위 폴더의 `.gitignore` 는 그 폴더에만 적용된다.** `api-vault/.gitignore` 가 `credentials/`·`API_KEYS_FORM.txt`·`reference_data/**` 를 막고 있고, 저장소 루트(`mini_t6/.gitignore`)에도 `**/credentials/`·`**/API_KEYS_FORM.txt`·`.env`·`.env.*` 를 중복으로 넣어 두었다. **첫 커밋 전에 `git status` 와 `git check-ignore -v <경로>` 로 두 파일이 실제로 제외되는지 확인한다.** 이미 추적 중인 파일은 `.gitignore` 추가만으로 제거되지 않으며, 한 번이라도 커밋되면 이력에서 지워도 노출된 것으로 보고 즉시 재발급한다.
