================================================================
api-vault  —  API 키 보관·관리 폴더
================================================================

특정 프로젝트에 묶여 있지 않습니다.
어느 프로젝트에서나 폴더째 복사해 쓰면 됩니다.


----------------------------------------------------------------
폴더 구조
----------------------------------------------------------------

api-vault/
├── README.txt                    이 파일
├── .gitignore                    키·데이터가 커밋되지 않게 차단
│
├── API_KEYS_FORM.txt        ★ 여기서만 작업합니다
│                                 API 별 설명 + 키 입력란
│                                 [키] = 오른쪽에 키를 붙여 넣으세요
│
├── credentials/                  자동 생성 영역 (직접 건드리지 않음)
│   ├── .env                      build_env.py 가 만듭니다
│   └── .env.bak                  직전 버전 백업
│
├── registry/
│   └── api_registry.csv          발급 대장 (상태·발급일·만료일·한도)
│
├── docs/
│   └── 발급_남은목록.txt         아직 신청하지 않은 API 목록
│
├── specs/                        API 명세 보관
│   └── README.txt                (OpenAPI/Swagger, PDF 매뉴얼 등)
│
├── reference_data/               파일데이터 원본 (API 아님)
│   ├── README.txt
│   ├── customs/                  관세청 HS부호·관세율표
│   └── ksure/                    무역보험공사 국가신용등급
│
└── scripts/
    ├── api_keys.py               키 로더 모듈 (외부 패키지 의존 없음)
    ├── build_env.py              입력표 → .env 생성
    └── check_keys.py             설정 현황 점검


----------------------------------------------------------------
사용 흐름 (이 세 단계가 전부입니다)
----------------------------------------------------------------

   1) API_KEYS_FORM.txt 를 열어
      [키] = 오른쪽에 발급받은 키를 붙여 넣는다

   2) python scripts/build_env.py
      → credentials/.env 가 자동으로 만들어진다

   3) python scripts/check_keys.py
      → 어떤 키가 설정됐고 무엇이 남았는지 확인

   키를 새로 발급받을 때마다 1~3 을 반복하면 됩니다.
   .env 를 직접 고칠 필요가 없습니다.


----------------------------------------------------------------
다른 프로젝트에서 쓰는 법
----------------------------------------------------------------

[방법 A] 폴더째 복사 (권장)

   프로젝트 안에 api-vault 를 통째로 넣고:

     import sys
     sys.path.insert(0, "api-vault/scripts")
     from api_keys import get_key, require_key

     key = require_key("ECOS_API_KEY")

[방법 B] 한 곳에 두고 여러 프로젝트가 공유

     import sys
     sys.path.insert(0, r"C:\\Users\\사용자\\api-vault\\scripts")
     from api_keys import get_key

[방법 C] python-dotenv 를 이미 쓰는 프로젝트

     from dotenv import load_dotenv
     load_dotenv("api-vault/credentials/.env")


----------------------------------------------------------------
api_keys 모듈
----------------------------------------------------------------

  get_key("ECOS_API_KEY")        키 반환. 없으면 None
  require_key("ECOS_API_KEY")    키 반환. 없으면 예외 발생
  available()                    값이 채워진 키 이름 목록
  missing()                      아직 값이 없는 키 이름 목록

  탐색 순서
    1) 이미 설정된 OS 환경변수   ← 배포 환경에서 우선
    2) api-vault/credentials/.env
    3) 현재 작업 폴더의 .env

  이미 설정된 환경변수는 덮어쓰지 않습니다.
  Render, PythonAnywhere 같은 배포 환경에서는
  플랫폼의 환경변수 설정이 그대로 우선 적용됩니다.


----------------------------------------------------------------
reference_data — 파일데이터에 대해
----------------------------------------------------------------

  아래 자료는 API 가 아니라 CSV·XLSX 다운로드입니다.
  Provider 를 만들 필요 없이 파일을 직접 읽으면 됩니다.

    customs/  관세청_HS부호
              관세청_품목번호별 관세율표
              관세청_국가별 관세율표 (국가별 폴더)
    ksure/    한국무역보험공사_국가신용등급

  주의
   - CSV 를 Excel 로 열어 저장하지 마세요.
     숫자형 코드(3818.00 → 3818)가 깨지고 한글이 손상될 수 있습니다.
   - 파일명 끝의 날짜는 받은 시점입니다. 갱신 시 새로 받아 날짜를 바꾸세요.
   - 용량이 커서 git 에서 제외됩니다(.gitignore).


----------------------------------------------------------------
발급 대장 (registry/api_registry.csv)
----------------------------------------------------------------

  컬럼
    status        발급완료 / 미신청 / 다운로드완료 / 키불필요
    provider      발급 기관
    api_name      API 이름 (포털 검색어와 동일하게)
    env_var       이 API 가 쓰는 환경변수 이름
    portal        발급처 도메인
    issued_date   발급일
    expires_date  만료예정일   ← 만료 전에 갱신 필요
    daily_limit   일일 호출 한도
    doc_url       문서 주소
    note          비고

  ※ 대장에는 키 값을 적지 않습니다. 환경변수 이름만 적습니다.


----------------------------------------------------------------
보안 규칙
----------------------------------------------------------------

  1. API_KEYS_FORM.txt 와 credentials/ 는 절대 Git 에 올리지 않는다
     (.gitignore 에 이미 포함되어 있음)

  2. 키를 채팅, 공유 문서, 스크린샷에 붙여 넣지 않는다

  3. 로그에 키를 출력하지 않는다
     check_keys.py 도 앞 4자리와 길이만 표시한다

  4. 공공데이터포털 인증키는 활용자당 1개다

  5. 실수로 커밋했다면 키를 즉시 재발급한다
     (커밋 기록에서 지워도 이미 노출된 것으로 본다)
